# 🎨 知识库文档 Markdown 格式、样式与图表校验规约 (Markdown Linting Rules)

本规约定义了 AI Agent（Gemini / Antigravity）在完成 `knowledgeBase` 知识库或任何 Markdown 技术文档编写后，**必须执行的自动化格式校验、排版样式审查与图表防报错红线**。

---

## 一、 Mermaid 图表语法与防报错红线

1. **【禁止危险连线语法】**：
   * **严禁**使用带管道的虚线/重线写法：如 `-.->|label|`、`===|label|` 或 `===>|label|`。此类语法在 Obsidian、GitHub 及多种 Markdown 渲染器中会直接触发 `Parse error` 导致画面崩溃。
   * **标准替代**：一律使用标准的双引号连线 `--> "label"`、`-->|label|` 或 `-- "label" -->`。

2. **【网络/子图布局方向控制】**：
   * 在使用 `graph TD` 或 `graph LR` 绘制多阶段子图（`subgraph`）时，若子图之间未显式连接，部分渲染引擎会倒序呈现（例如 4 ➔ 3 ➔ 2 ➔ 1）。
   * **强制修复**：子图之间必须显式添加依赖连接线（如 `Scenario1 ==> Scenario2 ==> Scenario3`）或绝对流向声明，确保顺序 top-to-bottom 或 left-to-right 呈现。

3. **【连线标签最高兼容性规约 (`-- "label" -->` 避坑红线)】**：
   * 所有带文字说明的 Mermaid 连线，**一律优先推荐使用标准的 `-- "label" -->` 格式**（如 `BridgeCheck -- "是 (br0 / docker0)" --> BrForward`）。
   * **绝对避免**使用未带双引号的 `-->|带括号或斜杠|` 管道选择器写法。
   * **原理解析**：在各种 IDE（如 VS Code、Obsidian、GitHub）内置的不同版本 Mermaid 渲染器中，未带引号的括号 `()` 或斜杠会被词法分析器错判为 `STADIUMEND` / `PE` 等节点形状符，直接抛出 `Parse error: got 'PS'`。使用 `-- "label" -->` 可实现 100% 全平台跨版本零报错兼容！

4. **【文本字符转义】**：
   * Mermaid 节点文本中如包含尖括号（如 `<table_name>`、`<pid>`）、括号或管道符 `|`，必须在双引号内转义或包含在反引号 `` ` `` 中，防止被解析为 HTML 标签或语法分隔符。

---

## 二、 Markdown 链接与路径规范

1. **【相对路径强制要求】**：
   * 知识库内部的所有超链接必须统一使用**清洁的 Markdown 相对路径**（如 `[CRI.md](../01-组件原理/04-Kubelet/CRI.md)` 或 `./Lifecycle.md`）。
2. **【绝对路径与乱码禁止】**：
   * **绝对禁止**写入包含 `file:///...` 或经过百分号编码的 URL 乱码路径（如 `file:///Users/.../%E7%BB%84%E4%BB%B6...`）。此类路径在跨机器或预览时会直接报 404 或显示为一串乱码。

---

## 三、 排版样式与文本标记规范

1. **【HTML 标签未转义防崩】**：
   * 正文中出现的尖括号变量（如 `<pod-name>`、`<namespace>`），在非代码块区域中**必须置于反引号 `` ` `` 内**。直接暴露在常规 Markdown 文本中会被部分渲染器误判为未闭合的 HTML 标签，导致后续整段文本格式崩坏。

2. **【写完后必须执行的 4 项自动校验步骤】**：
   每当 AI 完成一个文档的撰写或大面积扩充后，必须静默运行或自我检查：
   - [ ] **校验 1**：检索是否存在 `\-\.\->` 或 `===>`。
   - [ ] **校验 2**：检索是否存在 `file:///` 硬编码绝对路径。
   - [ ] **校验 3**：检查所有 ``` 代码块是否成对封闭。
   - [ ] **校验 4**：检查 Mermaid 节点 label 中是否有未转义的 `<` 和 `>`。
